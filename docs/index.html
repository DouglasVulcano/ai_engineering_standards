The problem

AI agents are only as consistent as the config you feed them. Left loose, it drifts.

A different rulebook per repo

Every project grows its own improvised CLAUDE.md, so the same agent behaves differently everywhere.

Advice with no teeth

A tidy guideline document that no pipeline checks. Standards rot the moment they are optional.

Setup that never finishes

The real value needs a scaffolder, a CI gate, and branch protection, all wired by hand, one repo at a time.

The standard

Four pillars, always in force

Applied whenever an agent starts, plans, or reviews work.

1

Workflow and governance

Issue-first, PR-driven. Every task is an Issue; every deploy is a PR that references it (Closes #N). Conventional Commits, feeding a canonical AGENTS.md with a thin CLAUDE.md import.

2

Motion and UI/UX

Skeleton, lazy loading, and smooth enter, exit, loading, and progress states. Honor prefers-reduced-motion; animate only transform and opacity.

3

Observability, quality, testing

OpenTelemetry to any backend, and an ordered capability gate: fmt, lint, typecheck, arch, deadcode, test, coverage, build. Stack-agnostic by design.

4

Arsenal

The right tool per task: shadcn-ui-mcp, 21st.dev Magic, chrome-devtools-mcp, design-motion-principles, web-design-guidelines, and humanizer, with a vetting checklist before adding any MCP.

Issue and PR templates, CODEOWNERS, a stack-aware CI gate, AGENTS.md plus a thin CLAUDE.md, and a safety deny-list. Idempotent, never overwrites without --force.

FAQ

Common questions

What is AI Engineering Standards?

A single, stack-agnostic engineering standard for AI coding agents, packaged as a Claude Code plugin and skill, with a governance scaffolder. It turns loose per-repo config into one versioned source of truth for workflow, UI, observability, quality, and testing.

How do agents apply it?

The skill triggers on its own when a request matches (creating an issue or PR, reviewing UI, setting up observability, following the standards), and loads only the relevant domain. It also feeds a canonical AGENTS.md that Claude Code, Cursor, Copilot, and other agents read directly.

Does it lock me into a specific stack?

No. Pillar 3 is a set of capability contracts (fmt, lint, typecheck, arch, deadcode, test, coverage, build), not a fixed toolset. A per-stack appendix maps each verb to JS/TS, Python, Go, Rust, JVM, and .NET.

How is the standard actually enforced?

The skill is advice; CI plus branch protection are the authoritative gate. The scaffolder wires a stack-aware CI gate and prints (or applies) branch protection, in both the classic API and the newer Ruleset model.

Which agents and models work with it?

Any agent that reads AGENTS.md. It is designed model-agnostic, so the same standard applies whether you run Claude Code, Codex, Cursor, or Copilot.
